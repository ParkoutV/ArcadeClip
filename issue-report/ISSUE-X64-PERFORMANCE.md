# [개선 제안] 프리뷰·영상 분석 성능 및 메모리 관리 개선 — Windows x64 릴리즈

전달 상태: `improved-performance.patch`에 공통 개선과 x64 헬퍼 빌드·동봉 코드를 담았습니다.
기존 인식 패치와 함께 사용할 때는 `apply-improvements.py` 및 `performance-compat/`를
사용하면 적용 순서에 맞는 보정본을 선택합니다. 아래의 현재 구현 설명은 로컬 ARM 작업본과
x64 이식에 필요한 검토 항목을 구분한 것입니다. x64 실기기 GPU·전체 릴리즈 검증은 아직 별도입니다.

## 요약

프록시 영상 없이 원본 영상을 사용하면서, 프리뷰의 불필요한 이미지 변환과 영상 분석 중 메모리 보유를 줄이고 싶습니다. 분석에서는 필요한 프레임만 이미지로 변환하고, GPU 디코딩과 GPU 이미지 변환을 독립적으로 선택하며, 가능한 경로에서 디코딩·변환·판독을 겹쳐 처리하는 개선을 제안합니다.

아래 내용은 앞선 로컬 작업에서 구현한 변경사항을 정리하여 정식 x64 릴리즈에 반영하자는 제안입니다. 특히 **3번 인식 영역 화면과 4번 클립 확인 화면에서 사용하는 공통 프리뷰 개선**, 인식 영역의 잘린 이미지 미리보기, 영역 지정 예시 영상까지 포함합니다. 로컬 구현 여부와 x64 릴리즈 검증 완료 여부는 구분합니다.

릴리즈 대상은 **Windows 10·11 x64**입니다. ARM 포팅, ARM용 의존성 교체, 별도 아키텍처의 OCR 보조 런타임 구성은 이 이슈 범위에서 제외합니다.

### 의존성·배포 조건의 구분

- **사용자가 Python·FFmpeg·추가 라이브러리를 별도 설치하지 않고 실행하는 조건은 유지합니다.** 필요한 실행 파일·패키지·DLL은 릴리즈 폴더에 포함합니다. Windows 구성 요소와 GPU 드라이버는 시스템 제공 기능을 사용합니다.
- 원본 x64 빌드도 이미 standalone 배포와 FFmpeg 동봉 절차를 갖고 있습니다. 이를 이번에 새로 추가한 개선이나 ARM 포팅에서 가져올 변경으로 취급하지 않습니다.
- 프리뷰는 기존 PySide6의 Qt Quick/Multimedia 기능을 사용합니다. 새로운 제3자 Python 패키지를 추가하는 변경은 아니지만 필요한 Qt 모듈과 QML 리소스가 번들에 포함되어야 합니다.
- 분석용 GPU 이미지 변환에는 **원본에 없던 자체 제작 네이티브 헬퍼 DLL**을 추가했습니다. `run/gpu_roi.c`를 빌드한 것으로, 외부 업체 라이브러리를 별도 설치하는 방식은 아닙니다. 다만 새 DLL과 그 빌드 단계가 생기는 것은 분명한 추가 의존성입니다.
- 따라서 아래 x64 헬퍼 지침은 현재 GPU 변환 구현을 채택할 때 필요한 작업입니다. “원본에 없던 DLL이나 빌드 의존성도 추가하지 않는다”는 조건까지 적용한다면 현재 구현은 그 조건을 충족하지 않으며, GPU 변환 경로의 재설계가 필요합니다. 프리뷰·메모리·CPU 이미지 변환 기반 파이프라인 개선은 별도로 반영할 수 있습니다.
- Zig는 현재 로컬 헬퍼의 빌드 도구이며 사용자 실행에 필요한 설치 항목이 아닙니다. x64 빌드에 Zig 도입을 필수로 요구하지 않고, 기존 빌드 도구 사용 가능성부터 확인합니다.

## 개선 전 문제

- 프리뷰에서 매 프레임 CPU 이미지 변환, 숨겨진 영역 미리보기 갱신, 재생 위치 변경에 따른 불필요한 UI 갱신이 발생합니다.
- 분석에서 최종 판독에 쓰는 프레임은 일부지만, 하드웨어 디코딩 경로에 따라 선택 전 모든 프레임이 CPU 메모리로 내려올 수 있습니다.
- 프레임 메타데이터 참조 순환과 처리 완료 이미지의 수명 때문에 긴 영상에서 메모리가 점진적으로 증가할 수 있습니다.
- GPU 디코딩과 이미지 변환을 묶어서 켜면 장치별로 유리한 조합을 선택하기 어렵습니다.

## 제안하는 변경사항

### 1. 원본 기반 프리뷰 개선

#### 공통 프리뷰의 GPU 표시와 지연 이미지 변환

- 기존 `QVideoFrame.toImage()` → CPU `QImage` → QWidget 그리기 경로 대신, `QQuickWidget`과 QML `VideoOutput`으로 영상 표시를 처리하도록 구현했습니다.
- 일반 재생의 프레임 수신에서는 매번 CPU 이미지를 만들지 않습니다. 크롭 미리보기 등 실제 픽셀 소비자가 `canvas.image`를 요청할 때만 변환하고, 같은 프레임의 스냅샷은 재사용합니다.
- 캔버스가 직접 보유하는 현재 프레임과 CPU 스냅샷은 각각 하나로 제한하며, 새 프레임이 오면 이전 스냅샷을 무효화합니다. Qt·디코더 내부 버퍼 전체가 한 장이라는 의미는 아닙니다.
- 영상 크기는 프레임 메타데이터에서 가져옵니다. 화면 맞춤, 영역 좌표 편집, 프로필 크기 확인만을 위해 전체 이미지를 변환하지 않습니다.

#### 확대·축소·이동·크롭과 영역 오버레이 유지

- 확대·축소와 이동은 표시 사각형에 적용합니다. 저장하는 인식 영역은 원본 기준의 정규화 좌표를 유지하므로, 표시 배율 때문에 판독 영역이나 저장 결과가 바뀌지 않습니다.
- 영역 테두리·라벨·보정된 자켓 영역은 영상 위의 별도 투명 오버레이에 그립니다. 오버레이는 마우스 입력을 가로채지 않아 기존 드래그 조작을 유지합니다.
- 영상 프레임이 바뀔 때마다 정적인 영역 표시를 다시 그리지 않습니다. 영역 편집, 표시 크기, 확대·이동 등 필요한 변화에 맞춰 갱신합니다.
- 레터박스, 역방향 드래그, 화면 맞춤, 회전·반전이 있는 영상의 표시와 원본 좌표 관계를 유지합니다. 프리뷰의 반전 지원과 분석용 GPU 변환의 지원 범위는 별도로 검증합니다.
- 프레임 단위 이동과 정확한 정지 프레임 표시는 기존 기능을 유지합니다. 대규모 인접 프레임 캐시나 프록시 파일은 추가하지 않았습니다.

#### 인식 영역의 잘린 이미지와 가이드 영상

- 3번 화면에서 선택한 영역의 작은 이미지 미리보기는 패널이 보일 때만 생성합니다. 4번 클립 확인 등으로 이동해 패널이 숨겨지면 크롭 갱신 타이머를 멈춥니다.
- 재생 중 크롭 갱신은 **150ms 간격**으로 제한합니다. 영역 편집, 일시정지, 패널 재표시 시에는 즉시 갱신하여 편집 반응성을 유지합니다.
- 영역 지정 예시를 보여주는 가이드 영상도 동일한 GPU 표시 캔버스를 사용합니다. 예시 영상 때문에 매 프레임 `toImage()`를 호출하지 않습니다.
- 패널을 숨길 때 가이드 재생을 중지하고, 종료할 때 가이드 플레이어·출력·프레임 참조를 정리합니다.

#### 탐색 요청과 타임라인 갱신

- 슬라이더와 타임라인을 빠르게 드래그할 때 첫 탐색은 즉시 실행하고, 이후 요청은 **40ms 타이머 구간에서 최신 목표만 유지**하도록 구현했습니다.
- 드래그가 끝난 뒤 마지막 요청 위치가 반영되며, 영상 교체 시 이전 영상의 대기 탐색 요청을 취소합니다.
- 재생 위치 알림은 전체/확대 타임라인의 재생 위치 값만 바꾸고, 보이는 타임라인만 갱신합니다. 매번 클립 목록을 다시 구성하지 않습니다.

#### 영상 교체·종료와 소프트웨어 경로

- 종료 및 영상 교체 시 재생 중지 → 출력 분리 → 소스와 프레임 참조 정리 순서를 적용하고, 이전 소스의 지연 프레임 신호가 새 화면에 반영되지 않도록 유지합니다.
- 앱 전역 이벤트 필터와 가이드 영상 자원도 해제합니다. 반복 생성·종료, 재생 중 종료, 연속 소스 교체를 회귀 검사 대상으로 둡니다.
- QML 로딩 실패나 headless 테스트 환경에서는 소프트웨어 표시 경로를 유지합니다. 진단 시 `ARCADECLIP_PREVIEW_RENDERER=software`로 명시적으로 선택할 수 있습니다.
- 이 GPU 프리뷰 경로는 3번 화면의 **분석용 GPU 디코딩·이미지 변환 옵션과 별개**입니다. 분석 옵션을 끈다고 프리뷰의 GPU 표시까지 끄는 구조는 아닙니다.
- GPU 표시 사용만으로 하드웨어 디코딩·무복사 전송·특정 FPS를 보장하지 않습니다. 과거 네이티브 오류 대화상자의 원인은 확정되지 않았으므로, 종료 처리 개선을 그 오류의 확정 수정으로 표현하지 않습니다.

#### 프리뷰 변경의 검토 위치

| 구현 항목 | 주요 소스 및 검사 |
| --- | --- |
| GPU 영상 표시·오버레이·지연 스냅샷 | `src/preview.py`, `src/assets/preview.qml` |
| 표시 좌표·회전·반전·프레임 이동 | `src/preview.py`, `src/tests/test_preview.py` |
| 크롭 갱신 제한·숨김 처리·가이드 영상 | `src/profile_panel.py`, `src/tests/test_app.py` |
| 최신 탐색 목표·재생 위치 갱신·종료 | `src/preview.py`, `src/app.py` |
| 실제 렌더러·수명 검사 | `run/verify_preview.py`, `run/verify_preview_lifecycle.py` |

로컬에서는 프리뷰·앱 회귀 검사와 실제 렌더러의 재생, 영역 편집, 회전·반전, 소스 교체·종료 검사를 수행했습니다. GPU 표시만 필요한 재생에서 CPU 스냅샷 생성이 없음을 확인한 기록도 있습니다. 이는 **x64 릴리즈의 재검증을 대체하지 않으며**, 크롭 미리보기를 켠 상황까지 CPU 변환이 전혀 없다는 의미는 아닙니다. 검증 스크립트의 로컬 런타임 경로는 x64 배포 경로에 맞춰 사용해야 합니다.

### 2. 필요한 프레임과 영역만 이미지 변환

- 원본 영상 디코딩은 유지하되, 시간 기준으로 선택한 샘플만 RGB 이미지로 변환합니다.
- GPU 디코딩 시 샘플 선택 전 모든 프레임을 CPU로 다운로드하지 않도록 GPU 소유 프레임 경로를 사용합니다.
- 전체 영상의 곡 판독에서는 가능한 경우 지정한 인식 영역을 먼저 잘라 색상 변환·다운로드합니다.
- 위치 보정, 현재 화면 확인, 경계 정밀 확인, 최종 OCR과 저장은 기존의 원본 영상 접근 범위를 유지합니다.
- **특정 공간 영역만 디코딩하는 기능은 포함하지 않습니다.** 디코딩과 이미지 변환은 서로 다른 작업입니다.
- GPU 영역·색상 변환은 지원되는 SDR 포맷부터 적용하고, 지원하지 않는 장치·포맷에서는 경고와 함께 CPU 경로로 이어갑니다. 회전, 색상 행렬과 색 범위를 검증합니다.

### 3. 프레임 수명과 메모리 관리

- PyAV 프레임의 `side_data` 접근으로 생길 수 있는 참조 순환과 네이티브 프레임 메모리 회수 지연을 관리합니다. 단순히 이미지 변수를 삭제하는 것만으로 해소됐다고 판단하지 않습니다.
- 현재 구현의 네이티브 메모리 추정량 기준 주기적 GC 방식을 x64에서도 검증하고, 일시정지 비용과 메모리 증가율을 함께 측정합니다.
- 처리 완료한 이미지, 최초 작업 묶음, 취소된 작업의 큐·프레임 참조를 해제합니다.
- 이전 이미지 비교나 경계 확인에 실제로 필요한 참조는 유지합니다. 살아 있는 참조를 강제로 해제하거나 메타데이터 검사를 생략하지 않습니다.
- 시스템 전체 RAM 대신 프로세스 전용 메모리와 필요 시 GPU 메모리를 따로 측정합니다. 결과 메타데이터 증가와 큰 프레임 버퍼 누적을 구분합니다.

### 4. 3번 화면에서 GPU 옵션과 파이프라인 선택

상세 설정을 열지 않아도 **3번 인식 영역 화면의 분석 시작 버튼 위**에서 다음 옵션을 변경할 수 있게 합니다.

| 옵션 | 동작 |
| --- | --- |
| GPU 영상 디코딩 | 영상 압축 해제에 GPU 사용 여부 선택 |
| GPU 이미지 변환 | 선택된 프레임의 영역·색상 변환에 GPU 사용 여부 선택 |
| 디코딩·변환·판독 겹쳐 처리 | 한 영상 안에서 순서를 유지하며 각 단계를 병행 |

- CPU/CPU, GPU/CPU, CPU/GPU, GPU/GPU 네 조합을 지원하고 실제 사용 경로를 표시합니다.
- CPU 디코딩+GPU 변환은 선택 프레임 업로드, GPU 디코딩+CPU 변환은 선택 프레임 다운로드 비용이 있습니다. 어느 조합이 항상 빠르다고 가정하지 않습니다.
- 옵션을 저장하고 분석 시작 시 값을 고정합니다. 실행 중 변경은 막으며, 상세 설정을 열어도 컨트롤이 3번 화면에서 사라지지 않아야 합니다.
- 기본값은 GPU 옵션 꺼짐, 겹쳐 처리 요청 켜짐으로 두고 x64 검증 후 조정할 수 있습니다.
- 단계 사이 대기 큐는 각각 최대 2개로 제한합니다. 처리 중 프레임과 기존 판독 묶음의 메모리는 별도로 고려합니다.
- 여기서 일괄 처리는 **한 영상 내부의 작은 묶음 처리**입니다. 여러 영상의 작업 목록 기능은 포함하지 않습니다.

**경계 프레임 인식 방식은 기존 구현을 그대로 유지해야 합니다.** 기존 CPU 단일 판독 작업자의 경계 버퍼가 필요한 경로에서는 앞서 읽기를 제한하고 순차 처리합니다. GPU 디코딩 및 기존 병렬 판독 경로에서도 기존 경계 정밀 확인 절차를 변경하지 않습니다.

## Windows x64 릴리즈 작업

현재 로컬 변경사항 전체를 그대로 배포하면 안 됩니다. 특히 `src/gpu_image.py`는 ARM64 조건과 전용 DLL 이름이 고정되어 있고, `run/build_gpu_roi.py`도 ARM64 대상 빌드입니다. **현재 GPU 변환 구현이 x64에서 검증 완료된 상태는 아닙니다.** 공통 D3D11 처리 소스를 활용하되 아래 작업을 먼저 완료해야 합니다.

- [ ] 기존 x64 빌드 경로인 `run/build_windows.ps1`, `run/pysidedeploy.spec`, `.github/workflows/release.yml`에 공통 개선사항만 반영합니다.
- [ ] D3D11 변환 헬퍼를 x64로 빌드하고 x64 DLL 로더를 구현합니다. 지원 여부는 실제 장치 초기화 결과로 확인합니다.
- [ ] 기존 x64 standalone의 Python·PyAV 내부 FFmpeg·저장용 FFmpeg·Qt·OCR 동봉을 유지합니다. GPU 변환 구현을 채택할 경우 새 x64 헬퍼도 동봉합니다. ARM 바이너리와 별도 아키텍처 OCR 브리지는 제외합니다.
- [ ] `preview.qml`, Qt Qml/Quick/QuickWidgets 및 필요한 QML 플러그인과 x64 헬퍼 DLL이 배포물에 포함되는지 확인합니다.
- [ ] Python이나 시스템 FFmpeg가 설치되지 않은 Windows x64 환경에서 프리뷰·분석·OCR·저장을 검증합니다.
- [ ] 기존 standalone 폴더 배포 방식을 유지하고 `ArcadeClip-<version>-windows-x64.zip`으로 패키징합니다. EXE 하나만 복사하는 배포 방식으로 안내하지 않습니다.
- [ ] `src/updates.py` 버전, 태그, ZIP 이름을 일치시키고 기존 라이선스·의존성 고지 절차를 유지합니다.
- [ ] 초안 릴리즈에서 검증한 뒤 공개합니다. 지원되지 않는 GPU 환경에서도 CPU 기능은 정상 작동해야 합니다.

## 완료 기준과 검증 기록

- [ ] x64에서 CPU/GPU 네 조합과 겹쳐 처리 켜짐·꺼짐을 비교하고, 실패 시 CPU 복귀를 확인합니다.
- [ ] 변환 횟수가 전체 디코딩 프레임 수가 아닌 선택 샘플 수와 일치합니다.
- [ ] 회전·영역 좌표·색상·샘플 시각과 판독 결과를 CPU 기준과 비교합니다.
- [ ] 기존 경계 결과가 유지되고, CPU 단일 작업자의 경계 버퍼 사용 경로가 변경되지 않습니다.
- [ ] 긴 영상의 예열 이후 메모리가 프레임 수에 비례해 계속 증가하지 않습니다. 완료·취소·재실행 시 작업 스레드와 프레임 참조가 정리됩니다.
- [ ] 프리뷰 확대·축소·이동·영역 편집·탐색·프레임 이동·영상 교체·종료가 정상입니다.
- [ ] 3번 인식 영역과 4번 클립 확인에서 같은 원본 위치·영역 좌표를 유지합니다. 숨긴 크롭 패널은 이미지를 추출하지 않고 다시 열면 갱신됩니다.
- [ ] GPU 표시만 필요한 재생에서 매 프레임 CPU 스냅샷이 생성되지 않습니다. 크롭을 켠 경우에는 실제 갱신 주기에 맞춰 생성됩니다.
- [ ] 빠른 탐색 후 최종 위치가 반영되고, 영상 교체 뒤 이전 소스의 대기 요청·프레임이 표시되지 않습니다. 가이드 재생과 소프트웨어 표시도 확인합니다.
- [ ] 옵션 저장, 실행 중 비활성화, 상세 설정을 연 뒤 위치 유지가 정상입니다.
- [ ] Intel/AMD/NVIDIA 등 확보 가능한 실제 x64 장치의 드라이버·코덱별 결과를 기록합니다. GPU 없는 CI의 성공만으로 GPU 검증을 대체하지 않습니다.
- [ ] 동일 영상·동일 구간·동일 설정으로 전체 소요시간, 디코딩·변환·판독 시간, 프로세스 메모리 증가율을 기록합니다. 겹쳐 실행한 단계 시간의 합을 전체 소요시간으로 해석하지 않습니다.

## 검토할 소스와 범위 제외

- 프리뷰: `src/preview.py`, `src/assets/preview.qml`, `src/profile_panel.py`, `src/app.py`
- 샘플링·메모리·GPU 변환: `src/video_sampling.py`, `src/media.py`, `src/gpu_image.py`, `run/gpu_roi.c`
- 판독 파이프라인·옵션: `src/jacket_recognition.py`, `src/pipeline.py`, `src/recognition.py`, `src/workspace_ui.py`, `src/advanced_settings.py`, 관련 번역·테스트
- 제외: ARM 전용 빌드·런처·의존성 잠금·패키징, ARM 배포물, ARM 실행을 위한 `ocr_bridge.py`·`ocr_worker.py` 및 관련 호출부 변경

위 파일 목록은 검토 위치이며 파일 전체를 그대로 적용하라는 의미는 아닙니다. 공통 기능과 포팅 코드가 섞인 파일은 변경 구간별로 분리해야 합니다.

동일 자켓 판독 재사용 및 Free Play 달성률 초기화에 따른 반복 플레이 구분은 이미 별도 이슈로 게시했으므로 이번 제안에서 제외합니다. 해당 내용의 기존 `recognition-improvements.patch`도 이번 이슈의 첨부 대상에서 제외합니다.
